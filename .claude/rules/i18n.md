# Localization rules

OmniToaster is bilingual from Phase 0, not localized later. English (`en-US`)
is the source of truth and Bahasa Melayu (`ms-MY`) is a first-class language,
switchable at runtime with no restart and no data migration.
[`docs/10-i18n.md`](../../docs/10-i18n.md) is the spec; `PROPOSAL.md` §6 is the
authority behind it.

## The two files

```
locales/en-US/omni_toaster.ftl
locales/ms-MY/omni_toaster.ftl
```

Embedded in the exe with `rust-embed`, resolved through Fluent
(`i18n-embed`, `i18n-embed-fl`, the `fl!()` macro). The user may place override
files of the same names under `OmniToasterData/locales/`; an override that fails
to parse is ignored with a logged warning and the embedded text is used.

Every key exists in **both** files, added in the **same commit**. CI fails the
build when the two key sets differ, so a key added to one file only breaks the
branch rather than shipping as English text in a Malay UI.

## Edit locale files with the Edit tool. Never a heredoc.

An unquoted heredoc expands `$name` and backticks, so `{ $time }` silently
becomes `{  }` and the message is dropped. The only symptom is a parse error
count in the log and a failing locale test — the mangled line looks fine in a
diff until you look closely. If you must script an edit, write the script to a
file and run it; quote the heredoc (`<<'EOF'`) if you use one at all.

## Keys

- Lowercase, hyphenated, grouped by the prefixes in `PROPOSAL.md` §6.2:
  `tray-`, `toast-`, `settings-`, `prayer-`, `weather-`, `reminder-`,
  `announce-`, `error-`, `format-`.
- A key is a stable identifier. `prayer-fajr` and `weather-rain` are stored in
  the database as built-in keys, so **renaming one needs a migration** — don't
  rename a key to tidy it up.
- A translator context comment goes above each key in the `.ftl` file, saying
  where the string appears and what any variable holds.

## Writing strings

- **Never concatenate translated fragments.** Word order differs between the two
  languages, so pass a Fluent variable and let the message own the sentence:
  `toast-snoozed-until = Snoozed until { $time }`, not a label plus a formatted
  time glued together in Rust.
- **Never format a date, a time or a number by hand.** `ot-i18n` has one
  formatter and it is the only thing that formats them — the toast, the tray
  tooltip and the speech service all call it. Malay uses `d/m/yyyy`, 24-hour by
  default, with Malay day and month names from static tables; English follows
  the Windows regional setting with the 12- or 24-hour choice left to the user.
- Spoken announcements come from Fluent templates with variables
  (`announce-time-ms = Sekarang pukul { $hour } { $minute }.`), never from
  strings assembled in code.
- **User-written text is never translated.** A reminder title is stored exactly
  as typed, with `authored_lang` recorded. A custom template title stays in the
  language it was written in; "Use default text" restores the built-in text in
  the active language.
- Casing follows [ui.md](ui.md): Title Case for labels and menu items, sentence
  case for hints, bodies, toasts and errors — in both files.

## Malay specifics

- Spelling and terminology follow **Dewan Bahasa dan Pustaka (DBP)**. The
  variant is Malaysian Malay (`ms-MY`); Jawi script is out of scope.
- **Prayers carry both names.** Settings always shows "Subuh (Fajr)",
  "Zohor (Dhuhr)", "Asar (Asr)", "Isyak (Isha)", "Syuruk (Sunrise)",
  "Jumaat (Jumu'ah)", so a user of either set can find the prayer. The prayer
  **identifier** never changes with language.
- Malay text may be up to **30% wider** than English. Lay out and snapshot with
  the longest Malay string, and build the pseudo-locale (about 40% longer) to
  catch what Malay does not.
- Currency defaults to `RM` in Malay and `MYR` in English, and the user may set
  any code.

## Fallback

A missing Malay key falls back to English **and logs a warning**. That warning
is the signal that a key went into one file only; it is not an acceptable
steady state, and the key-parity check in CI is what stops it shipping.

## Paperwork

- Every translation change gets a `CHANGELOG.md` line.
- A translation change that alters meaning gets a `docs/GOTCHAS.md` entry under
  "Localization and Fluent".
- Malay translations are reviewed by a named native speaker before Phase 9.
- Developer documents stay in English. `README.md` (English) and `README.ms.md`
  (Malay) each link to the other.
