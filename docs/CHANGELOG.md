### Added

- Added `ot-core::paths` (FEAT-0002): the one place that decides where Omni Toaster may write. `DataRoot::resolve` takes `--data-dir` or falls back to `OmniToasterData/` beside the executable, creates the whole subtree on first run, and proves the folder is writable by writing and deleting a probe file rather than by reading permissions — which still says yes on a full disk or a read-only mount. `DataRoot::join` is the only way to build a path inside the root: it refuses `..`, absolute and drive-prefixed paths before touching the filesystem, so it works for files that do not exist yet, and re-checks with `canonicalize` where the target does exist, so a symlink pointing out of the root is refused too. Errors are a typed `PathError` whose variants stay separate because the advice a user needs differs. Verified in the running app both ways: the subtree appears under a scratch `--data-dir`, and an ACL-denied folder is reported with its OS cause, exits 1 and is left completely untouched.
- Added minimal `--data-dir` and `--version` handling to the binary, so the data root can be exercised in the running app. FEAT-0006 still owns the real command line — `--self-test`, `--worker` and a bilingual `--help`. A `--data-dir` with no folder is an error rather than a silent fallback, because falling back would write into the real `OmniToasterData/` on a typo.
- Created the Cargo workspace and its eleven members (FEAT-0001): the `omnitoaster` binary, which builds as `OmniToaster.exe` and reports its version, and the ten library crates `ot-core`, `ot-i18n`, `ot-store`, `ot-platform`, `ot-ui`, `ot-toast`, `ot-sched`, `ot-prayer`, `ot-weather` and `ot-media`. With `rust-toolchain.toml` pinning stable on `x86_64-pc-windows-msvc`, `.cargo/config.toml` adding `+crt-static`, and `deny.toml` restricting the project to permissive licences and banning `openssl-sys`. The whole gate is green and the 223 KB exe imports only `KERNEL32.dll` and `ntdll.dll`, so the static CRT is confirmed rather than assumed.
- Set the workspace-wide lints in one place — `unsafe_code`, `clippy::unwrap_used`, `todo` and `dbg_macro` all `warn`, with every member opting in — because the project rules forbid a crate-wide `allow` and the gate turns warnings into errors.
- Filed and closed BUG-0001. A branch push created no `ci.yml` run, which looked like the `on.push` filter's `!` negation being unsupported; pushing the next branch disproved it, with `ci.yml` triggering in seconds and the filter untouched. The cause was a transient outage of the forge's Actions dispatch — the runner logged `502 Bad Gateway` fetching tasks in exactly that window. No code changed; the diagnostic order is now a GOTCHAS entry.
- Committed `keys/minisign.pub`, the verifying half of the release signing key, and proved the pair: a signed local packaging run of 0.1.0 verifies with `rsign verify` against the committed public key, producing all six contract assets with every manifest size and SHA-256, and every `SHA256SUMS.txt` entry, agreeing with the real files. Signing through the forge secret rather than a local key file is still unproven, and `verify-release.ps1` still needs a published release, so FEAT-0009's Test box stays open.
- Added `.gitattributes`. `core.autocrlf` is on here, so a fresh checkout rewrote the working copy of every file git touched — the symptom being a one-line patch arriving as "every line changed", which GOTCHAS records having hidden a real diff. The repository now stores LF and says so, and `keys/*.pub`, `*.minisig` and `SHA256SUMS.txt` are marked `-text` so signed and hashed material stays byte-exact; a CRLF in a checksum file would have surfaced as a verification failure inside a release job instead of here.
- Recorded that the packaging script copies `THIRD_PARTY_NOTICES.md` into the zip only when the file exists, and it does not, so the 0.1.0 zip has none. Harmless while the workspace has no third-party dependencies, and tracked in FEAT-0009 against the first release that does. `docs/09-ci-cd-and-releases.md` no longer claims the file is always present.
- Recorded that `release.yml` stops being harmless once a workspace exists: its plan step skips everything while there is no `Cargo.toml`, so documentation pushes to `main` were green and published nothing, but with the workspace in place and a `feat:` commit in history it plans `0.1.0` and fails at signing. Run 5 on `main` failed exactly that way. The failure is contained — no tag pushed, no release created, `main` untouched — but **every further push to `main` will fail the same way** until the owner generates the minisign keypair, commits `keys/minisign.pub` and sets `OT_MINISIGN_KEY` on both forges. FEAT-0009 is `Blocked` on that.
- Added `scripts/build-and-package.ps1`, which both release workflows already called although it did not exist: it builds `OmniToaster.exe`, checks the binary reports the version being released, assembles the portable zip with a `README.txt` that explains portable mode and verification, writes `manifest.json` (with `min_supported_version` and `data_schema`), signs it with rsign, writes `SHA256SUMS.txt` and `CHANGELOG-<version>.md`, and fails if any member of the asset contract is missing. It has been parsed, never executed — there is no workspace to build until FEAT-0001.
- Added `keys/README.md`: how the minisign keypair is generated (unencrypted, because an encrypted key hangs a runner waiting for a console password), where the public half is committed and embedded, how the `OT_MINISIGN_KEY` forge secret is configured, and how the key is rotated by shipping the new public key one release early.
- Added `.gitignore`: `target/`, `OmniToasterData/`, the release staging folder, every private key form, and everything in `keys/` except `README.md` and `minisign.pub`.
- Filed FEAT-0009 for the release packaging work, recording what is still open after the above: `keys/minisign.pub` (the owner generates the keypair), the Pester tests for the release planner, and the forge secret rename.
